## 1. Overview

Implement a new Java OSGi module to call the **NISA API** (Network Infrastructure Service API) from Smallworld Magik, following the exact same architecture as the existing `rwwi_astri_integration_java` module.

NISA differs from ASTRI in its **authentication mechanism**:
- ASTRI uses HTTP Basic Auth (Base64 username:password in every request header)
- NISA uses **JWT Bearer Token Auth** — must first POST to `/authentication/gettoken`, receive a `muse_token`, then pass it as `Authorization: Bearer <token>` in subsequent calls

### 4.2 `NisaAuthClient.java` — Authentication (Internal)

Responsible for obtaining the JWT token from NISA. Called by `NisaMassProblemClient` before every API request (or when token is missing/expired).

**Endpoint:**
```
POST https://apinisa.oss.myrepublic.co.id/api/authentication/gettoken
Content-Type: application/json

{
  "userid": "fms.team",
  "password": "1e2e535ee0b11d459df6735596b46b05"
}
```

**Response (relevant fields):**
```json
{
  "success": true,
  "muse_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

**Key behavior:**
- Parses JSON response using regex (same approach as ASTRI - no external JSON library)
- Returns the `muse_token` string if `"success": true`
- Throws an exception with details if `success` is false or token is missing
- Token is **not cached** between calls (stateless, simple) — re-fetched per `NisaMassProblemClient` call
  - Note: Could be cached later if performance is a concern, but keeping simple for V1

### 4.3 `NisaMassProblemClient.java` — Mass Problem API (Internal)

Calls the mass problem endpoint using Bearer token from `NisaAuthClient`.

**Endpoint:**
```
POST https://apinisa.oss.myrepublic.co.id/api/transaction/massproblem/active/cluster
Authorization: Bearer <muse_token>
Content-Type: application/json

{
  "cluster": "<cluster_code>"
}
```

**Response:** Raw JSON string returned as-is to Magik (Magik code parses it).

**Key behavior:**
1. Instantiates `NisaAuthClient` and calls `getToken()`
2. Builds POST request with `Authorization: Bearer <token>` header
3. Sends body `{"cluster": "<cluster_value>"}`
4. Returns raw JSON response body


### 4.4 `NisaMassProblemProcs.java` — Magik Proc (Exposed)

The **only public API surface** exposed to Magik via `@MagikProc` annotation.

```java
package com.rwi.myrepublic.nisa;

public class NisaMassProblemProcs {

    @MagikProc(@Name("nisa_get_massproblem_active_cluster"))
    public static Object getMassProblemActiveCluster(Object proc, Object clusterCode) {
        // 1. Convert Magik string → Java string
        String cluster = MagikInteropUtils.fromMagikString(clusterCode);

        // 2. Call client
        NisaMassProblemClient client = new NisaMassProblemClient();
        String jsonResponse = client.getMassProblemActiveCluster(cluster);

        // 3. Return JSON string to Magik
        return MagikInteropUtils.toMagikString(jsonResponse);
    }
}
```

**Magik usage:**
```magik
json_result << nisa_get_massproblem_active_cluster("CLUSTER-001")
```

## 11. Key Differences from ASTRI

| Aspect | ASTRI | NISA |
|--------|-------|------|
| Auth type | HTTP Basic (every request) | JWT Bearer (2-step: gettoken → use token) |
| Auth endpoint | None (embedded in header) | `POST /authentication/gettoken` |
| Auth credentials in | Base64 header | JSON body `{userid, password}` |
| Token lifetime | N/A | Unknown (per JWT `exp` claim) — re-fetch each call for V1 |
| Response format | XML (WorkOrders), JSON (others) | Raw JSON (returned as-is to Magik) |
| Config property prefix | `astri.*` | `nisa.*` |
| Magik proc prefix | `astri_*` | `nisa_*` |

## 12. Assumptions & Notes

1. **Token re-fetch per call (V1):** Each `nisa_get_massproblem_active_cluster()` call first fetches a fresh token. This is safe and simple. If token caching is needed later (for performance), add an in-memory cache with expiry checking.

2. **JSON response returned raw:** The mass problem endpoint response is returned as a raw JSON string to Magik. The Magik caller parses it using `json_parser` (same as ASTRI vendor/device endpoints).

3. **No external JSON library:** JSON parsing uses regex (same approach as all ASTRI clients). This keeps the JAR dependency-free and consistent with the existing pattern.

4. **HTTPS:** The NISA base URL uses HTTPS (`https://`). Java's `HttpClient` handles TLS automatically with the system's default truststore. No special SSL configuration needed unless the cert is self-signed.

5. **`cluster` body field:** The POST body `{"cluster": "<value>"}` matches the API spec. The field name is `cluster` (lowercase).

6. **Product registration:** The new module will be added to `pni_custom/product.def` so it loads with the product.
