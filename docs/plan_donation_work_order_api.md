## 1. Overview

This document describes the implementation plan for fetching **Donation Work Order** data (Cluster & Subfeeder donation values) from the ASTRI API and integrating the result into the existing BOQ generation workflow.

### 1.1 API Specification

| Field            | Value                                                                   |
| :--------------- | :---------------------------------------------------------------------- |
| **Route**        | `/v4/work-order/cluster/propose-donation/list/all/{limit}/{offset}`     |
| **Method**       | `POST`                                                                  |
| **Content-Type** | `application/json`                                                      |
| **Auth**         | Basic Auth — same credentials as all other ASTRI endpoints              |
| **Base URL**     | Same as existing work order calls (`AstriConfig.getApiBaseUrl()`)       |

Full example URL: `{base_url}/work-order/cluster/propose-donation/list/all/500/0`

### 1.2 Request Body (JSON) — Standard Filters

```json
{
    "assigned_vendor_name": "--not internal",
    "latest_status_name":   "--not cancelled",
    "permit_status":        "DONATION APPROVED"
}
```

> No `target_cluster_code` filter here — the button fetches **all** valid donation WOs in one call, then matches them against the loaded list locally.

### 1.3 Key Response Fields

| Field | Type | Description |
| :---- | :--- | :---------- |
| `success` | boolean | `true` on success |
| `count` | integer | Records in this page |
| `count_all` | integer | Total matching records |
| `data[].number` | string | WO Number (primary match key) |
| `data[].target_cluster_code` | string | Cluster code (secondary match key) |
| `data[].target_cluster_final_donation_value` | string | **Used when infra_type = "cluster"** |
| `data[].target_cluster_subfeeder_donation_value` | string | **Used when infra_type = "subfeeder"** |

### 1.4 Key Difference from Existing Work Order API

Existing work order endpoints use **GET** with query params (see `WorkOrderClient.java`).  
This donation endpoint uses **POST** with a **JSON body** — a new internal Java client is required.

## 2. Architecture Alignment

This module follows the established **Procs + internal Client** pattern:

```
Magik global procedure  astri_get_donation_work_orders(...)
        ↓  auto-generated by @MagikProc annotation
AstriDonationWorkOrderProcs.java    (public, annotated bridge)
        ↓  delegates to
internal/DonationWorkOrderClient.java  (HTTP POST client, Java 11 HttpClient)
        ↓  reads config from
AstriConfig                         (singleton: base URL + credentials)
```

Response format: **JSON → XML** (same conversion as `WorkOrderClient` / `AstriWorkOrderProcs`), consumed by `simple_xml` in Magik.

## 3. Behaviour Description

### 3.1 "Get Donation WO" Button — Scope and Placement

**Placement:** In the **filter/pagination toolbar** (`build_toolbar2` method), placed **beside the "Apply Filters" button** — NOT in the detail panel button row.

**Scope:** Operates on the **entire currently loaded list** (all entries in `.wo_cache`), not on the selected WO.

**Enable/disable rules:**
- Disabled by default (on dialog open).
- **Enabled** after a list is loaded: when `.wo_cache` is not empty **AND** `.filters[:infrastructure_type] ≠ "feeder"`.
- **Disabled** when list is empty OR infra_type filter = "feeder" (donation API not applicable to feeder).
- Button state is refreshed at the end of `workorder_list_data()` and `apply_filters()`.

**On click (`get_donation_work_orders_for_list()`):**
1. Checks `.wo_cache` is not empty and infra_type is not "feeder".
2. Calls `astri_get_donation_work_orders(500, 0, filters)` once with the 3 standard filters — no specific cluster code, to retrieve all valid donation WOs in one API call.
3. Builds an in-memory lookup map from the response: `wo_number → donation_value` (and `cluster_code → donation_value` as fallback).
4. Iterates over all entries in `.wo_cache`; for each WO, looks up its `donation_value` by `wo[:wo_number]` (then by `wo[:infra_code]` as fallback).
5. Stores `donation_value` directly into each WO property_list in `.wo_cache`.
6. Also updates `.selected_wo[:donation_value]` if a WO is currently selected.
7. Logs summary: how many WOs received a donation value.

**Donation field selected by infra_type:**
- `"cluster"` → `target_cluster_final_donation_value`
- `"subfeeder"` → `target_cluster_subfeeder_donation_value`

### 3.2 BOQ Generation — Using Donation from Selected WO

When `generate_boq_json()` or `generate_boq_excel()` is triggered:

1. Reads `donation_value` from `.selected_wo[:donation_value]` — which was already populated by the list-level button.
2. If `_unset` or empty (user didn't press the button), **auto-fetches** for just the selected WO by calling the API with `target_cluster_code = wo[:infra_code]`, then stores the result.
3. Passes `:donation_value` in `boq_params` to the BOQ generator.
4. If infra_type = "feeder" or value is unavailable after auto-fetch, continues BOQ without RT/RW Permit.

### 3.3 RT/RW Permit Material Rule

| Field | Value |
| :---- | :---- |
| Name | `RT/RW Permit` |
| Object category | `other` |
| Material code | `500002155` |
| `material_slot` | `:both` (has both material AND service quantity) |
| `qty_material` | Always `1` |
| `qty_service` | `donation_value` (numeric, converted via `.as_number()`) |
| **Generated only if** | `donation_value` is present and parseable as a number |

## 5. Detailed Implementation Steps

### Step 1 — `DonationWorkOrderClient.java` (new)

**File:** `src/main/java/com/rwi/myrepublic/astri/internal/DonationWorkOrderClient.java`

- Standalone class — mirrors `WorkOrderClient` structure.
- Uses `java.net.http.HttpClient` (Java 11+) with `AstriConfig` for base URL and credentials.
- Endpoint: `{base_url}/work-order/cluster/propose-donation/list/all/{limit}/{offset}`.
- Sends HTTP **POST** with `Content-Type: application/json` body.
- Parses JSON response and converts to XML (same pattern as `WorkOrderClient`).

**XML response structure:**
```xml
<response>
  <success>true</success>
  <count>50</count>
  <count_all>50</count_all>
  <data>
    <workorder>
      <number>WO/ALL/2025/.../54556</number>
      <target_cluster_code>PLB006435</target_cluster_code>
      <target_cluster_final_donation_value>150000</target_cluster_final_donation_value>
      <target_cluster_subfeeder_donation_value>75000</target_cluster_subfeeder_donation_value>
      <latest_status_label>Approved</latest_status_label>
    </workorder>
    ...
  </data>
</response>
```

**Method signature:**
```java
public String getDonationWorkOrders(int limit, int offset, String jsonBody)
    throws IOException, InterruptedException
```

### Step 2 — `AstriDonationWorkOrderProcs.java` (new)

**File:** `src/main/java/com/rwi/myrepublic/astri/AstriDonationWorkOrderProcs.java`

Creates global Magik procedure `astri_get_donation_work_orders` — identical pattern to `AstriWorkOrderProcs`.

**Magik procedure signature:**
```magik
astri_get_donation_work_orders(limit, offset, _optional filters)
## Parameters:
##   limit   - integer: max records to return (use 500 for list-level fetch)
##   offset  - integer: pagination offset (0-based)
##   filters - optional property_list with keys:
##               :assigned_vendor_name  (e.g. "--not internal")
##               :target_cluster_code   (optional, omit for list-level fetch)
##               :latest_status_name    (e.g. "--not cancelled")
##               :permit_status         (e.g. "DONATION APPROVED")
##               :target_cluster_name
## Returns:
##   XML string — parsed in Magik with simple_xml
```

**Java bridge (mirrors `AstriWorkOrderProcs`):**
```java
@MagikProc(@Name("astri_get_donation_work_orders"))
public static Object getDonationWorkOrders(Object proc, Object limit, Object offset,
                                           @Optional Object filters) {
    try {
        int limitInt  = MagikInteropUtils.fromMagikInteger(limit);
        int offsetInt = MagikInteropUtils.fromMagikInteger(offset);
        String jsonBody = buildJsonBody(filters); // Magik property_list → JSON string

        DonationWorkOrderClient client = new DonationWorkOrderClient();
        String xmlResponse = client.getDonationWorkOrders(limitInt, offsetInt, jsonBody);
        return MagikInteropUtils.toMagikString(xmlResponse);
    } catch (Exception e) {
        return MagikInteropUtils.toMagikString(buildErrorXml(e.getMessage()));
    }
}
```

`buildJsonBody(filters)` converts the Magik `property_list` (via `MagikInteropUtils.fromMagikPropertyList`) into a JSON string, including only non-null filter keys. `target_cluster_code` is omitted when calling for the full list.

### Step 3 — `rwwi_astri_workorder_dialog_donation.magik` (new)

#### 3a. `get_donation_work_orders_for_list()` — button action (list-level)

```magik
#% text_encoding = iso8859_1
_package user
$

_pragma(classify_level=debug, topic={astri_integration})
_method rwwi_astri_workorder_dialog.get_donation_work_orders_for_list()
    ## Fetch donation values for ALL work orders in the current loaded list.
    ## Stores donation_value in each WO entry in wo_cache.
    ## Called by the "Get Donation WO" button beside Apply Filters.

    _if .wo_cache _is _unset _orif .wo_cache.empty?
    _then
        _self.user_info("No work orders loaded. Apply filters first.")
        _return
    _endif

    _local infra_type << .filters[:infrastructure_type].default("cluster").lowercase
    _if infra_type = "feeder"
    _then
        _self.user_info("Donation WO is not applicable for Feeder infrastructure.")
        _return
    _endif

    # Determine which response field to read
    _local donation_field << _if infra_type = "cluster"
                             _then >> "target_cluster_final_donation_value"
                             _else >> "target_cluster_subfeeder_donation_value"
                             _endif

    _self.log_info("Fetching donation values for all work orders in list...")

    # Call API once with standard filters — no cluster code filter, get all
    _local filters << property_list.new_with(
        :assigned_vendor_name, "--not internal",
        :latest_status_name,   "--not cancelled",
        :permit_status,        "DONATION APPROVED")

    _local xml_response << astri_get_donation_work_orders(500, 0, filters)

    _if xml_response _is _unset _orif xml_response = ""
    _then
        _self.log_error("Empty response from donation API.")
        _return
    _endif

    _try
        _local xml_obj   << simple_xml.read_string(xml_response)
        _local data_node << simple_xml.element_named(xml_obj, "data")

        _if data_node _is _unset
        _then
            _self.log_error("No data node in donation API response.")
            _return
        _endif

        # Build lookup: wo_number -> donation_value and cluster_code -> donation_value
        _local by_wo_number    << equality_hash_table.new()
        _local by_cluster_code << equality_hash_table.new()

        _for wo_node _over data_node.xml_contents.fast_elements()
        _loop
            _local num_node << simple_xml.element_named(wo_node, "number")
            _local val_node << simple_xml.element_named(wo_node, donation_field)
            _local cod_node << simple_xml.element_named(wo_node, "target_cluster_code")

            _if val_node _isnt _unset
            _then
                _local val << val_node.xml_contents.first.default("")
                _if num_node _isnt _unset
                _then
                    by_wo_number[num_node.xml_contents.first.default("")] << val
                _endif
                _if cod_node _isnt _unset
                _then
                    by_cluster_code[cod_node.xml_contents.first.default("")] << val
                _endif
            _endif
        _endloop

        # Apply donation values to all WOs in wo_cache
        _local matched   << 0
        _local unmatched << 0

        _for cache_key _over .wo_cache.keys()
        _loop
            _local wo  << .wo_cache[cache_key]
            _local val << by_wo_number[wo[:wo_number].default("")]
            _if val _is _unset
            _then
                # Fallback: match by infra_code (cluster code)
                val << by_cluster_code[wo[:infra_code].default("")]
            _endif

            _if val _isnt _unset
            _then
                wo[:donation_value] << val
                matched +<< 1
            _else
                unmatched +<< 1
            _endif
        _endloop

        # Also update selected_wo if one is currently selected
        _if .selected_wo _isnt _unset
        _then
            _local cached << .wo_cache[.selected_wo[:infra_code].default("").as_symbol()]
            _if cached _isnt _unset _andif cached[:donation_value] _isnt _unset
            _then
                .selected_wo[:donation_value] << cached[:donation_value]
            _endif
        _endif

        _self.log_success(write_string(
            "Donation fetch complete — matched: ", matched,
            " | unmatched: ", unmatched))

    _when error
        _self.log_error("Failed to process donation response: " +
                        condition.report_contents_string)
    _endtry
_endmethod
$
```

#### 3b. `fetch_donation_value_for_wo(wo, infra_type)` — private helper for BOQ auto-fetch

Used only by BOQ methods when `selected_wo[:donation_value]` is missing.  
This call **includes** `target_cluster_code` to narrow the API response to just that WO.

```magik
_pragma(classify_level=debug, topic={astri_integration})
_private _method rwwi_astri_workorder_dialog.fetch_donation_value_for_wo(wo, infra_type)
    ## Fetch donation value for a single work order (used by BOQ auto-fetch).
    ## Calls API with target_cluster_code filter to narrow results.
    ##
    ## Returns: donation value string, or _unset if not found.

    _local filters << property_list.new_with(
        :assigned_vendor_name, "--not internal",
        :target_cluster_code,  wo[:infra_code].default(""),
        :latest_status_name,   "--not cancelled",
        :permit_status,        "DONATION APPROVED")

    _local donation_field << _if infra_type = "cluster"
                             _then >> "target_cluster_final_donation_value"
                             _else >> "target_cluster_subfeeder_donation_value"
                             _endif

    _local xml_response << astri_get_donation_work_orders(100, 0, filters)

    _if xml_response _is _unset _orif xml_response = ""
    _then >> _unset
    _endif

    _try
        _local xml_obj      << simple_xml.read_string(xml_response)
        _local success_node << simple_xml.element_named(xml_obj, "success")
        _if success_node _is _unset _orif
            success_node.xml_contents.first <> "true"
        _then >> _unset
        _endif

        _local data_node << simple_xml.element_named(xml_obj, "data")
        _if data_node _is _unset _then >> _unset _endif

        _local wo_number     << wo[:wo_number].default("")
        _local matched_value << _unset

        # Search by WO number first
        _for wo_node _over data_node.xml_contents.fast_elements()
        _loop
            _local num_node << simple_xml.element_named(wo_node, "number")
            _if num_node _isnt _unset _andif
                num_node.xml_contents.first = wo_number
            _then
                _local val_node << simple_xml.element_named(wo_node, donation_field)
                _if val_node _isnt _unset
                _then
                    matched_value << val_node.xml_contents.first
                    _leave
                _endif
            _endif
        _endloop

        # Fallback: first result
        _if matched_value _is _unset _andif data_node.xml_contents.size > 0
        _then
            _local val_node << simple_xml.element_named(
                                   data_node.xml_contents.first, donation_field)
            _if val_node _isnt _unset
            _then matched_value << val_node.xml_contents.first
            _endif
        _endif

        >> matched_value

    _when error
        _self.log_error("Donation value fetch failed: " + condition.report_contents_string)
        >> _unset
    _endtry
_endmethod
$
```

## 7. Validation Checklist

| # | Scenario | Expected Result |
| :- | :------- | :-------------- |
| 1 | Dialog opens, no list loaded | "Get Donation WO" button disabled |
| 2 | Load cluster WOs via Apply Filters | "Get Donation WO" button enabled |
| 3 | Load subfeeder WOs via Apply Filters | "Get Donation WO" button enabled |
| 4 | Load feeder WOs via Apply Filters | "Get Donation WO" button remains disabled |
| 5 | Click "Get Donation WO" with cluster list | `donation_value` set from `target_cluster_final_donation_value` in every matched WO in cache |
| 6 | Click "Get Donation WO" with subfeeder list | `donation_value` set from `target_cluster_subfeeder_donation_value` in every matched WO in cache |
| 7 | Select a WO after button click | `selected_wo[:donation_value]` already populated from cache |
| 8 | Generate BOQ JSON — donation pre-populated | RT/RW Permit item in result: `qty_material=1`, `qty_service=<value>` |
| 9 | Generate BOQ JSON — donation NOT fetched | Auto-fetch for selected WO only; RT/RW Permit included if successful |
| 10 | Generate BOQ JSON — feeder WO | No auto-fetch; no RT/RW Permit in result |
| 11 | Donation API returns 400 or empty | Error logged; BOQ continues without RT/RW Permit |
| 12 | `donation_value` is non-numeric string | `.as_number()` returns `_unset`; RT/RW Permit silently skipped |
| 13 | Apply Filters reloads list | `wo_cache` is cleared and rebuilt; button state refreshed (donation values lost — user re-clicks button) |

## 8. Risks & Notes

| Risk | Mitigation |
| :--- | :--------- |
